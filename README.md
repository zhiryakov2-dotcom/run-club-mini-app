# RUN CLUB — исправленный Mini App

Бот: **@run_club_test_bot**
Репозиторий: https://github.com/zhiryakov2-dotcom/run-club-mini-app
Таблица: «Беговой_клуб_Mini_App_база»
Хостинг фронта: GitHub Pages (из репозитория)

## Что было сломано

1. **`script.js`: `API_URL = 'https://google.com'`** — это заглушка, а не API.
   `fetch('https://google.com')` возвращает HTML главной Google, `res.json()`
   падает, и приложение всегда показывает «Не удалось подключиться
   к Google Таблице». Бэкенда не существовало вовсе.
2. **В `index.html` не подключался `telegram-web-app.js`**, поэтому
   `window.Telegram` был `undefined`: не работали `tg.ready()`,
   `tg.expand()` и определение пользователя для записи.
3. **В таблице был только лист эстафет** (ID / Название / Год / Команда /
   Участники / Дата / Результат / Фото), а фронт ждал листы
   «События», «Объявления», «Участники». Их не было, и брать данные
   было неоткуда.
4. **Не было раздела «Эстафеты»** в приложении, хотя он есть и в
   описании (1.docx), и в таблице.
5. Запись на тренировку не передавала Telegram ID — один человек мог
   записаться много раз, а счётчик участников вообще не считался.

## Что в этой папке

| Файл | Назначение |
|---|---|
| `Code.gs` | Бэкенд на Google Apps Script: читает 5 листов, отдаёт JSON, принимает запись и добавление тренировок |
| `index.html` | Фронт + подключён `telegram-web-app.js` + вкладка «Эстафеты» |
| `script.js` | Фронт: нормальные ошибки, счётчик участников, защита от дублей, экранирование данных |
| `style.css` | Стили, меню на 6 вкладок |
| `api-example.json` | Пример ответа API — для проверки вёрстки без бэкенда (`index.html?demo=1`) |

## Подключение — 15 минут

### Шаг 1. Листы в таблице

Откройте таблицу «Беговой_клуб_Mini_App_база». Все 5 листов уже есть,
заголовки в первой строке должны быть такие (не меняйте порядок колонок —
`Code.gs` пишет строки позиционно под эти заголовки):

- **События:** `ID | Название | Тип | Дата | День недели | Время | Место | Описание`
  Тип — `Тренировка` или `Забег`. Дата — как `15.10.2026`.
- **Объявления:** `ID | Категория | Заголовок | Автор | Текст | Дата | Статус`
- **Участники:** `ID | Имя | Фото | Год вступления | Стаж бега | Дистанции | Цель | Темп`
- **Эстафеты:** `ID | Название | Год | Команда | Участники | Дата | Результат | Фото`
- **Записи:** `ID | Участник | Событие | Дата записи | Статус`
  Этот лист заполняется сам при записи, руками его вести не нужно.

Если лень создавать вручную — после шага 2 запустите функцию `setup()`,
она создаст недостающие листы сама.

### Шаг 2. Бэкенд в Apps Script

1. В таблице: **Расширения → Apps Script**.
2. Удалите содержимое `Code.gs` и вставьте файл `Code.gs` из этой папки целиком.
3. Пароль администратора уже задан в `Code.gs`: **runclub2026**.
   Он же вводится в Mini App при добавлении тренировки. Если захочешь
   другой — поменяй `ADMIN_PASSWORD` в `Code.gs` и сделай новое
   развёртывание.
4. Нажмите ▶ рядом с функцией **`setup`** и разрешите доступ.
   Проверьте, что листы создались.
5. Вернитесь в таблицу и добавьте пару строк в «События», например:
   `ОФП | 11.11.2026 | Среда | 19:00 | Манеж | Тренировка | Общая физическая подготовка`

### Шаг 3. Развёртывание веб-приложения

1. В Apps Script: **Развернуть → Новое развёртывание**.
2. Тип: **Веб-приложение**.
3. «Выполнять как»: **Я**.
4. «У кого есть доступ»: **Все** (Anyone) — иначе Mini App получит
   ошибку доступа, это самая частая причина «не подключается».
5. **Развернуть** → скопируйте URL вида
   `https://script.google.com/macros/s/AKfyc.../exec`

> После каждого изменения `Code.gs` нужно делать **новое развёртывание**
> (Развернуть → Управление развёртываниями → ✎ → Новая версия),
> иначе старый код продолжит работать. URL при этом обычно сохраняется.

### Шаг 4. Вставить URL во фронт

1. В `script.js` замените
   `const API_URL = 'ВСТАВЬТЕ_СЮДА_URL_WEB_APP';`
   на скопированный URL в кавычках.
2. Загрузите `index.html`, `script.js`, `style.css` в репозиторий
   `zhiryakov2-dotcom/run-club-mini-app` (ветка `main`), заменив старые.
   GitHub Pages обновится сам через 1–2 минуты (Deployments в репозитории).

### Шаг 5. Проверить

1. Откройте Mini App в Telegram у бота **@run_club_test_bot** → должна
   открыться главная с ближайшей тренировкой из таблицы, а не ошибка.
2. Проверьте вкладки: Календарь, Тренировки, Объявления, Эстафеты, Участники.
3. Нажмите «Я участвую» → в таблице на листе «Записи» должна появиться
   строка, а счётчик на главной — увеличиться.
4. Добавьте тренировку через Календарь с паролем из шага 2 — она должна
   появиться в списке.

## Проверка без бэкенда (только вёрстка)

Запустите локально `python3 -m http.server` в этой папке и откройте
`http://localhost:8000/index.html?demo=1` — данные возьмутся из
`api-example.json`. Это проверяет только внешний вид, не таблицу.

## Если снова «Не удалось подключиться»

- URL в `script.js` точно `/exec` и начинается с `https://script.google.com/macros/s/`?
- В развёртывании стоит доступ «Все», а не «Только я»?
- После правок `Code.gs` сделано новое развёртывание (новая версия)?
- Откройте URL `/exec` просто в браузере: должен вернуться JSON
  `{"ok":true,"events":[...],...}`, а не страница входа в Google.
  Если браузер показывает вход — доступ развёртывания не «Все».
